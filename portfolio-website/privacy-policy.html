2. Data We Collect

2.1 — Automatically Collected Data

When you visit this site, the hosting infrastructure (Vercel) may log standard server access data:

  • IP address (used for routing and rate limiting; see §4)
  • Browser user-agent string
  • Pages visited and timestamps
  • HTTP referrer

This data is collected by the hosting provider under their own privacy policy. We do not have direct access to raw IP logs from Vercel's edge network.

2.2 — AI Query Data (Thesis Assistant)

If you use the Thesis AI Query feature (when available), the following is logged:

  • Your question text (stored in our Supabase database)
  • A hashed representation of your IP address (SHA-256 with a private salt — not reversible)
  • The AI-generated answer preview (first 200 characters)
  • Response latency in milliseconds
  • Which thesis sections were retrieved to answer your query

Your question is sent to Google's Gemini API (for embedding generation via gemini-embedding-2 and answer synthesis via gemini-2.5-flash / gemini-2.0-flash-lite / gemini-2.0-flash, in that priority order). Google's data processing is governed by Google Gemini API Terms of Service and Google Privacy Policy. As of the effective date of this policy, Google does not use Gemini API inputs to train their models by default when accessed via the API with a valid key.

The system uses a retrieval-augmented generation (RAG) pipeline: your question is converted into a vector embedding, matched against pre-indexed thesis chunks stored in our Supabase vector database, and the top matching chunks are passed as grounding context to the Gemini generation model. No raw thesis text is transmitted unnecessarily.

2.3 — Research Logs (Authenticated Users Only)

If you authenticate (via Supabase Auth magic-link email), voluntary research log entries you create are stored and associated with your user account. These are visible only to you and to the site administrator.

2.4 — Data We Do NOT Collect

  • We do not use advertising trackers or third-party analytics (no Google Analytics, no Meta Pixel)
  • We do not sell or share your data with any third party for commercial purposes
  • We do not store raw IP addresses — only salted SHA-256 hashes
  • We do not use browser fingerprinting
  • We do not train any AI model on your queries

3. Legal Basis for Processing (GDPR)

For users in the European Economic Area (EEA), our legal basis for processing is:

  • Legitimate Interest (Art. 6(1)(f) GDPR): rate limiting to prevent abuse of the AI query endpoint
  • Consent (Art. 6(1)(a) GDPR): you voluntarily submit queries to the AI assistant
  • Contract (Art. 6(1)(b) GDPR): account data for authenticated researchers

4. Rate Limiting & Security

The AI query API is rate-limited to 10 requests per minute per IP using a sliding-window algorithm (Upstash Redis). This is a security measure to prevent denial-of-service attacks and excessive API usage. Rate limit decisions are made in real time and are not stored permanently.

Additional security measures include:

  • All traffic served over HTTPS (TLS 1.2+) via Vercel's edge network
  • API input validation and sanitization on all endpoints
  • Input length capped at 500 characters for AI queries to prevent prompt injection
  • Error tracking via Sentry with PII scrubbing enabled
  • Supabase Row Level Security (RLS) enforced on all tables
  • Service-role keys are server-side only; never exposed to the browser
  • CORS restricted to the deployed Vercel domain in production

5. Data Retention

  • AI query sessions: retained indefinitely for research quality improvement; you may request deletion at any time
  • Research logs: retained as long as your account exists; deleted upon account deletion
  • Hashed IP records: retained for 90 days for abuse investigation, then purged

8. Cookies & Local Storage

This site does not set any first-party tracking cookies. Supabase Auth uses a short-lived session token stored in localStorage (not a cookie) to maintain authenticated sessions. This token is scoped to this site and is not accessible to third parties. The Pyodide in-browser Python runtime stores WebAssembly packages in the browser's Cache API for performance — no personal data is cached.

9. In-Browser Computation (Pyodide)

The Slide 05 simulation runner uses Pyodide (CPython compiled to WebAssembly) to execute Python code entirely within your browser. No Python code or simulation results are transmitted to our servers. All computation happens locally on your device. Pyodide package downloads come directly from the Pyodide CDN (JsDelivr / GitHub Releases).

10. Children's Privacy

This site is an academic research portfolio and is not directed at children under 13. We do not knowingly collect personal data from children. If you believe a child has submitted data, contact us for immediate deletion.
